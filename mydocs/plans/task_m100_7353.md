## 목적과 범위

기여자가 표 조판 규칙을 추가·수정·삭제할 때 담당 모듈과 공통 결과의 소유자,
소비 경로 및 검증 계약을 찾을 수 있도록 구조를 개선한다. #7280의 SOLID/CQRS,
문단 중심 문서 구조와 책임 분리 원칙을 이어간다.

주 대상은 기준 devel에서 19,856줄인 `src/renderer/layout/table_layout.rs`다.
파일 크기 감소만으로 완료하지 않는다. 문단 내 텍스트·컨트롤 순서와 셀·중첩 표의
소유 관계를 유지하며, 조회/판단과 상태 변경/배치의 경계를 명시한다.

`table_layout.rs`뿐 아니라 `table_partial.rs`, `table_cell_content.rs`,
`typeset/table/*` 및 `height_measurer.rs`의 표 관련 책임을 함께 구조화한다.
#7280에서 분리한 모듈은 활용하며 표와 무관한 기능까지 재작성하지 않는다.
IR 전면 변경, 범용 동적 규칙 엔진, 조판 결함 수정은 제외한다.
기존 예외는 근거와 소비 경로를 기록하되 이동하면서 삭제·완화하지 않는다.

## 소스 구조와 의존 방향

파일 이동이 아니라 책임의 소유 위치를 체계화한다. 아래는 R1에서 실제 호출·타입 의존을
검증할 목표 구조 초안이며, 확정된 파일명이나 구현 완료 구조가 아니다.

```text
src/renderer/
├── table/                   # 표 콘텐츠·기하·분할 계산의 공통 도메인
│   ├── content/             # 셀 문단/컨트롤의 줄·유닛 구성
│   ├── measure/             # 행·셀·중첩 표의 점유 메트릭
│   ├── fragment/            # 컷·조각 요구 높이의 계산
│   └── contracts.rs        # 실제로 공유하는 결과·좌표·소유권 타입
├── typeset/table/           # 페이지 예산, 수용 결정, 예약 및 이월 상태 적용
└── layout/table/            # 결정된 전체/부분 표와 셀 콘텐츠의 실제 배치
```

- 공통 계산은 `LayoutEngine`이나 페이지 가변 상태, RenderTree에 의존하지 않도록 분리한다.
  필요한 메트릭 공급자는 좁은 입력/인터페이스로 받는다. 불필요한 trait는 만들지 않는다.
- `typeset/table`은 공통 계산 결과로 페이지 계획을 만들고, `layout/table`은 그 결과를
  소비한다. layout 결과를 다시 추측해 페이지 계획을 바꾸거나 상호 재귀 의존하지 않는다.
- `height_measurer.rs`는 표 계산의 공통 결과를 소비하는 진입점으로 정리한다.
  의미가 다른 기존 계산을 같은 이름 아래 강제로 합치지 않는다.
- 문단 중심 소유 관계와 TAC/자리차지/어울림 속성을 입력 계약으로 유지한다.
  같은 규칙을 전체 표·부분 표·중첩 표의 별도 파일마다 복제하지 않는다.
- 각 모듈의 진입점, 책임/비책임, 허용 의존성과 규칙별 테스트 위치를 연결한다.
  범용 `utils`나 거대 `rules.rs`에 책임을 다시 모으지 않는다.
- 새 테스트는 제품 소스가 아닌 `tests/cases/` 및 기존 별도 테스트 패키지에 둔다.
  `layout/tests.rs`의 기존 검증은 보존하고 이동 필요성을 함께 조사한다.
- R1에서 현재 → 목표 심볼 이동표와 의존 그래프를 작성한다. R4에서 금지 의존·순환과
  규칙의 중복 소유 여부를 검사한다. 단계적 위임 경로는 임시임을 표시하고 종료 조건을 둔다.

- 분리된 모듈의 책임/비책임, 입력·출력, 허용 의존성, 관련 정식 테스트 위치.

## 검증 원칙

현행 [로컬 검증 정책](../manual/pr_review/local_validation.md)과
[시각 검증 정책](../manual/verification/visual_verification_governance.md),
[Visual Sweep](../manual/verification/visual_sweep_guide.md)을 적용한다.
과거 리팩토링 전략의 테스트 개수·명령을 현행 CI 기준으로 재사용하지 않는다.

1. R1에서 고정한 base/head, 입력 해시, 실행 환경 및 기존 실패를 기록한다.
2. 각 묶음에서 컴파일·관련 경계 계약·영향 페이지를 먼저 확인한다.
3. 페이지 수뿐 아니라 내용 누락/중복, 조각 외곽·점유 높이·후속 내용 위치를 비교한다.
4. 테스트는 `tests/cases/` 및 별도 테스트 패키지 체계를 따른다. 파생 suite는 커밋하지 않는다.
5. 제출 전 현행 CI 대상 회귀와 native/WASM/workspace Clippy 묶음, base 고정 정책 검사,
   Docker fresh WASM 및 Native/WASM 직접 시각 비교를 수행한다.
6. 동일 SHA·입력·환경의 유효한 증거는 재사용한다. 코드 변경 시 영향 경로를 재검증한다.
7. 기존 실패·신규 회귀·미검증을 구분한다. baseline/golden/ignore를 완화하여 통과시키지 않는다.
