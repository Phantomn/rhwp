## 1. 변경된 목표

작업지시자의 “표 조판 전면 개선” 지시에 따라 기존 동작 보존·코드 이동 중심 계획을 대체한다.
표 조판 규칙을 명시하고 그 규칙을 공통 조판 결과로 구현한다. 잘못된 기존 동작까지 보존하지 않는다.
SOLID/CQRS와 문단 중심 소유 관계는 유지하되, 기존 CellUnit·RowCut·PartialTable 내부 모델도
필요하면 재설계한다. 공개 API·파서·직렬화 영향은 별도로 검토하며 호환성을 무단 변경하지 않는다.

전면 개선은 표 조판 영역의 구조·알고리즘 개선이다. 전체 문서 엔진·HFT 폰트 재작성,
범용 동적 규칙 엔진이나 표 관련 이슈의 검증 없는 일괄 종료를 뜻하지 않는다.

### 개발 방식: 기존 경로를 보존하고 신규 경로에서 구현

작업지시자의 권고에 따라 기존 표 조판 코드를 직접 개편하는 대신
`src/renderer/table_v2/`에 신규 경로를 만든다. 이 경로는 Git으로 관리하는 실험 구현이며
`/tmp`나 산출물 폴더가 아니다. 기존 파일을 먼저 이동·삭제하거나 대량 복사하지 않는다.

- 기본값은 `Legacy`다. 검증할 때 명시적으로 `V2`를 선택한다. 선택 전달 방식은
  Native/WASM 모두 사용할 수 있는 문서 조판 세션 설정으로 설계하며 공개 API 영향은 확정 후 구현한다.
- 기존 경로의 수정은 명시적 선택 진입점과 필요한 좁은 어댑터로 제한한다.
  공용 helper 변경으로 Legacy 동작까지 바뀌면 격리가 깨진 것이므로 별도 검증한다.
- 선택은 조판 세션 시작 때 고정한다. 부모 표와 모든 자식·이어받기 조각은 같은 경로를 쓴다.
  측정은 V2, 분할이나 paint는 Legacy인 혼합 경로를 만들지 않는다.
- V2 미지원 입력은 이유를 명시한다. 자동 fallback이나 문서 ID별 우회로 성공처럼 보이지 않게 한다.
  필요하면 사용자가 Legacy로 명시적으로 다시 실행할 수 있다.
- 복귀는 source rollback이 아니라 경로 선택 변경이다. 이미 계산한 컷·캐시·페이지 트리는 폐기하고
  원본 IR에서 재조판한다. 진행 중인 WASM continuation의 엔진을 중간에 바꾸지 않는다.
- 기본값 전환과 기존 경로 제거는 서로 별도 승인 단계다. 개발 완료 전에 복귀 경로를 제거하지 않는다.

## 2. 규칙과 독립 근거

규칙마다 `독립 근거 → 적용 조건/반례 → 결과 계약 → 구현 위치 → 실제 검증`을 연결한다.
사양이 설명하지 않는 조판 동작은 정상 생성 입력·대응 한컴 출력과 메인테이너 시각 판정을
사용한다. 기존 코드·통과 테스트·총 페이지 수만으로 규칙을 정하지 않는다.

| 규칙 축 | 구분할 계약 |
| --- | --- |
| 문단·소유 관계 | 텍스트/컨트롤 순서, 명시 개행, 저장/재조판 줄 소속, 부모/자식 경로 |
| 셀 기하 | 선언 폭·높이의 의미, 표 기본/셀 개별 여백, 병합 셀·행 간격·테두리 |
| 줄 점유 | 빈 줄의 글자모양·줄간격, 기준선·개체 바깥여백, 한 줄의 여러 TAC 객체 |
| 본문배치 | TAC는 줄 참여 속성, 자리차지와 어울림은 흐름/가용 영역 속성 |
| 분할 허용 | 나누지 않음·셀/행 분할·반복 제목·현재/다음 페이지 수용·빈 페이지보다 큰 객체 |
| 위치 기준 | 문단/단/본문/용지 원점, offset, 중첩 셀 내부 좌표계와 실제 가용 영역 |
| 이어받기 | 시작/끝 소유 범위, 남은 물리 밴드, 여백, rowspan·자식 표 재개 |
| 후속 흐름 | 캡션·각주·후속 문단, 예약 해제, 최종 조각 종료, 불필요한 빈 페이지 |

TAC라는 이유만으로 모든 표를 분할 금지하거나, 자리차지라는 이유만으로 항상 분할하지 않는다.
속성 조합·실제 줄 구성·가용 공간에 대한 규칙을 각각 입증한다.
한컴과 다른 출력도 규칙상 타당할 수 있다. 불명확한 경우 메인테이너 시각 트리아지로 결정한다.

## 3. 공통 조판 결과

```text
Document IR + 서식 + 유효한 저장 정보 + 조판 제약
  → TableContentPlan   셀별 줄·개체·자식 표의 소유 및 점유
  → TableFragmentPlan  페이지 예산에 맞춘 컷·기하·예약·재개 결과
      ├── typeset: 수용·흐름 전진·페이지/단 전이 반영
      └── layout: 확정 기하·소유 범위로 RenderTree 생성
```

위 이름은 설계 이름이며 아직 구현된 타입이 아니다. 전체 표도 같은 모델의 단일 조각으로 표현한다.
콘텐츠 구성은 폭·어울림 영역 등에 의존한다. 모든 페이지에 쓸 단일 고정 줄 목록으로 가정하지 않는다.
제약이 달라지면 해당 범위의 계획을 다시 생성하고 예약·배치가 같은 버전을 소비한다.

TableFragmentPlan은 다음 사실을 구분한다.

- 표/셀/문단/줄/컨트롤 소유자와 부모·자식 컷의 명시적 도메인.
- 가용 예산, 선택한 내용 범위, 요구 높이 및 누적 물리 점유.
- 셀·행·표 외곽 기하, 내용 원점, 여백·반복 제목의 점유.
- 자식 표 재개 상태, 이미 소비한 내용, 남은 빈 밴드, 종료 여부.
- 캡션·각주 예약 요청과 후속 흐름 전진량. 보이는 높이와 흐름 높이는 별개다.

레이아웃은 컷을 다시 추측하거나 예약보다 표를 더 키워 보정하지 않는다.
추가 요구가 발견되면 확정 전에 계획/fit 단계로 되돌려 재계산한다.
클리핑은 유효한 표시 경계 적용 수단이며 내용 누락·예산 오류를 숨기는 해결책이 아니다.

## 4. 소스와 상태 소유

```text
renderer/
├── table_v2/          # 신규 구현: 개발 중 명시적 선택
│   ├── contracts.rs   # 콘텐츠/조각/재개·좌표·소유권 계약
│   ├── context.rs     # 계산 환경·캐시·무효화
│   ├── content/       # 문단과 개체의 줄 구성·자식 표 관계
│   ├── measure/       # 줄/셀/행/표 기하
│   ├── fragment/      # 예산 fit·rowspan·재귀 분할·재개 계획
│   ├── placement/     # V2 결과로 실제 셀·표 배치, 외곽, 커서 조회
│   └── integration.rs # 문서 흐름·페이지 상태와 연결하는 좁은 어댑터
├── typeset/table/     # Legacy 보존
└── layout/
    ├── table_layout.rs       # Legacy 보존
    ├── table_partial.rs      # Legacy 보존
    └── table_cell_content.rs # Legacy 보존
```

- V2의 표 측정과 실제 배치는 같은 결과 계약을 소비한다. Legacy의
  `height_measurer.rs`는 보존하고 V2가 그 안의 표 보정을 암묵적으로 재사용하지 않는다.
- 공통 계산은 LayoutEngine/RenderTree/TypesetState에 직접 의존하지 않는다.
- 페이지 상태는 TypesetState, 계산 캐시는 계산 세션, 렌더 노드 상태는 layout이 소유한다.
- 캐시 key/유효성에는 결과에 영향을 주는 문서·서식 변경과 폭·가용 영역·profile을 반영한다.
  현재 pointer-key 방식의 수명 가정을 검토하며 자동으로 전역 공유하지 않는다.
- 편집 후 재조판, undo/redo, 저장 후 재열기, lazy cursor probe, Native/WASM 재개를 검증한다.
- `PageItem` 등 기존 소비자에 연결하는 어댑터를 둘 수 있지만 새 결과를 legacy 컷으로
  재추측하여 소유·높이를 잃지 않아야 한다. V2 결과와 Legacy 결과는 타입/태그로 구별한다.
  원본 IR·폰트·일반 paint 기반 기능의 공유와 Legacy 표 알고리즘 의존을 구분한다.

## 5. 구현 묶음

| 묶음 | 범위 | 완료 조건 |
| --- | --- | --- |
| R2 규칙/결과 설계 | 규칙 근거·반례, 신규 계획 타입·경로 선택/복귀 계약, 기준 출력 확보 | 기대값·입출력·소유권·Legacy 격리 확정 |
| R3 신규 종단 구현 | table_v2에서 줄 구성 → 측정 → 부모/자식 분할 → 예약 → 출력 | 명시적 V2 실행의 대표 사례 충족 및 Legacy 무변경 |
| R4 경계 확장 | rowspan·제목 반복·빈 줄·각주·캐시/편집·글상자·세로쓰기·backend | 적용/비적용 경계와 내용 완전성 입증 |
| R5 전환 판단 | 최신 devel 흡수, Legacy/V2/독립 기준 비교, 기본값 전환 검토 | CI·시각·호환성·복귀 증거, 전환 승인. Legacy 제거는 별도 |

함수 단위의 작은 승인 절편으로 나누지 않는다. 모든 경로를 한 번에 교체하지 않고 대표 종단
경로를 완성한 뒤 확장한다. V2 지원 범위는 문서 ID가 아닌 기능과 규칙으로 명시한다.
선택 장치의 임시 상태와 향후 정식 경로/이름으로 전환하는 조건을 문서화한다.
새 경로 실패 시 조용히 옛 경로로 fallback하여 통과를 위장하지 않는다.

기존 예외는 `유효한 규칙 / 근거 있는 호환 동작 / 잘못된 보정 / 미검증`으로 분류한다.
미검증 예외를 일반 규칙으로 승격하거나 근거 없이 전부 삭제하지 않는다.

## 6. 검증 및 완료 계약

정본: [로컬 검증](../manual/pr_review/local_validation.md),
[시각 판정 거버넌스](../manual/verification/visual_verification_governance.md),
[Visual Sweep](../manual/verification/visual_sweep_guide.md).

1. 수정 전 입력·출력·source SHA를 보존하되 기존 출력을 정답으로 고정하지 않는다.
2. 독립 기대값으로 계약을 작성한다. 결함 검출 주장은 수정 전 의도한 원인으로 FAIL,
   수정 후 PASS를 확인한다. 합성 입력과 정상 한컴 생성 입력의 증거를 구분한다.
3. 컷·유닛 소유, 요구/예약 높이, 실제 셀·표 외곽, 앞뒤 문단을 검사한다.
   페이지 수·문자 존재만으로 완료하지 않는다.
4. 기존 후보 #6923, #6935/#6803, #6601/#7150, #5702/#7158, 글상자/세로 셀은 유지하되
   assertion이 승인 규칙을 검사하는지 재검토한다. 틀린 과거 기대값은 근거 없이 유지하지 않는다.
5. 실패는 `규칙 위반 / 규칙상 타당한 한컴 차이 / 판정 보류`로 트리아지하고,
   전후 변화는 `의도된 개선 / 신규 회귀 / 기존 문제`로 별도 표시한다.
6. baseline/golden 변경에는 독립 근거와 메인테이너 승인을 연결한다.
   원인 미상 차이를 기준값 갱신·ignore로 숨기지 않는다.
7. 테스트는 `tests/cases/`와 별도 테스트 패키지에 둔다. private 검증을 위해 공개 API를
   불필요하게 확대하지 않으며 source unit-tier와 generated suite 정책을 따른다.
8. 영향 페이지 Native/fresh WASM compare·overlay·review를 직접 판독한다.
   편집/커서·종료·내용 중복/누락도 확인한다.
9. focused·시각 결과 공유 후 승인된 전체 nextest, native/WASM/workspace Clippy,
   Native Skia 등 현행 게이트를 실행한다. 동일한 유효 증거는 재사용한다.
10. 동일 입력을 Legacy와 V2에서 각각 독립 세션으로 실행하고 독립 기준과 함께 비교한다.
    두 경로에서 각주·예약·상태 변경을 같은 문서 세션에 중복 적용하지 않는다.
    실행 경로·SHA·입력·환경을 모든 증적에 기록한다. Legacy 통과를 V2 검증으로 세지 않는다.
11. 경로 선택의 기본값 유지, V2 미지원 보고, Legacy 재실행, 캐시/페이지 트리 분리,
    Native/fresh WASM의 동일 선택을 정식 계약으로 검증한다.

완료는 파일 수·줄 수 감소가 아니라 승인된 표 조판 규칙의 일관된 구현과 검증이다.
미검증 경로·유효한 한컴 차이·미해결 문제는 남겨 보고한다. 원격 push·PR 생성·merge와
개별 이슈 종료는 별도 승인 절차를 따른다.

## 현재 상태

R1 정적 조사와 unit-tier 정책 검사만 완료됐다. 기존 출력 기준선·조판 회귀·시각 검증은
미실행이다. 이번 개정은 설계 방향 반영이며 제품 코드 구현이나 검증 완료를 뜻하지 않는다.
